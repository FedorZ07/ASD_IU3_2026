# Отчёт по лабораторной работе № 2

## Задача 1A. Минимальная очередь с приоритетом

Реализована собственная двоичная минимальная куча на динамическом массиве.
При вставке новый элемент добавляется в конец и поднимается методом `siftUp`.
При извлечении минимум из корня заменяется последним элементом и восстанавливается
порядок методом `siftDown`. Ёмкость массива удваивается по необходимости.

Асимптотика и особенности расширения массива разобраны в `complexity-lab02.md`.

### Проверки

JUnit 5: пустая очередь, одиночный элемент, дубликаты, отрицательные числа,
вызовы `peek`, чередование операций, рост массива, строки и сравнение с
эталонной очередью на 10 000 случайных чисел.

### Результаты

Результаты локальной сборки и замеры производительности дополняются после
проверки в VS Code. Замеры задач выполняются отдельно в `benchmarks.md`.

## Задача 1B. Компаратор

Добавлен необязательный `Comparator`, чтобы переключаться между min-heap и max-heap.
Оба варианта используют одну и ту же реализацию просеивания; различается только сравнение.
Сравнение на 100 000 элементов воспроизводится через `BenchmarksMain`.

## Задача 1C. Удаление по значению

Поиск первого вхождения проводится линейно по массиву. После замены последним
элементом выбирается одно из двух просеиваний, чтобы восстановить кучу.

### Ручные проверки задачи 1C

- Для кучи с элементами `1, 4, 2, 5` вызов `remove(1)` должен вернуть `true`,
  после чего извлечение даёт `2, 4, 5`. Это проверяет удаление корня.
- Для кучи с элементами `2, 2, 2` один вызов `remove(2)` оставляет два
  элемента. Это проверяет удаление только одного вхождения.
- Для пустой очереди `remove(1)` должен вернуть `false`. Это проверяет
  граничный случай без обращения к несуществующим ячейкам.

Ручные примеры дополняют автоматические тесты: их легко повторить при защите
и объяснить, какую ветку алгоритма они проверяют.
